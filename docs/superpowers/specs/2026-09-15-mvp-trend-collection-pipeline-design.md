# MVP 트렌드 수집 파이프라인 — 설계 스펙

**작성일**: 2026-09-15
**관련 문서**: [PRD.md](../../../PRD.md)

## 배경

PRD 기준 핵심 기능 1번(콘텐츠 자동 수집)의 1차 MVP 하위 프로젝트.

데이터 소스는 다음 검토를 거쳐 확정했다:
- X(트위터)·인스타그램 공식 API는 무료로 트렌드 검색이 사실상 불가능(X는 읽기 권한이 유료 티어부터, Instagram Graph API는 본인 계정 데이터 위주)
- Reddit은 한국 시장 트렌드 파악에 적합하지 않음(영어권 중심 콘텐츠)
- 네이버 데이터랩 검색어트렌드 API는 "발견" 도구가 아니라 이미 아는 키워드(최대 5그룹, 그룹당 20개)의 상대적 검색량 추이만 비교하는 도구라, "뭐가 뜨는지 모르는 상태에서 찾아내는" MVP 목적에 맞지 않음
- 유튜브 데이터 API `videos.list?chart=mostPopular&regionCode=KR`는 키워드 사전 지정 없이 한국 인기 급상승 동영상을 바로 조회 가능하고 무료 쿼터가 충분(1회 호출 1유닛, 일 10,000유닛)

→ **MVP는 유튜브 인기 급상승(KR) 단일 소스**로 착수한다. 대시보드·슬랙 리포트·브랜드 콘텐츠 변환 제안·다른 소스 확장은 별도 하위 프로젝트로 이후 진행한다.

## 범위

- **포함**: 유튜브 인기 급상승(KR) 수집, Claude API 기반 키워드 추출, SQLite 저장, 수동 실행 파이프라인
- **제외 (후속 하위 프로젝트)**: 웹 대시보드, 슬랙 알림, 자동 스케줄링(Task Scheduler), X·인스타그램·네이버 등 다른 소스 연동, 브랜드 콘텐츠 변환 제안

## 아키텍처

```
유튜브 데이터 API (KR 인기 급상승)
              │
              ▼
   수집 스크립트 (Python, 수동 실행)
              │
              ▼
     Claude API (키워드 추출)
              │
              ▼
         SQLite DB
   (원본 콘텐츠 + 추출 키워드 + 활용 아카이빙)
```

하루 1회 사람이 스크립트를 실행하면, 유튜브 인기 급상승(KR) 목록을 조회하고(이미 순위가 매겨져 있으므로 별도 급등 필터링 불필요), Claude API로 키워드를 뽑아 SQLite에 쌓는다.

## 컴포넌트

| 파일 | 역할 |
|---|---|
| `youtube_collector.py` | 유튜브 데이터 API `videos.list?chart=mostPopular&regionCode=KR`로 인기 급상승 동영상 목록 수집 |
| `keyword_extractor.py` | 수집된 원문(제목/설명)을 Claude API에 보내 핵심 키워드 3~5개 + 활용 맥락 한 줄 요약 추출 |
| `storage.py` | SQLite 스키마 관리(`raw_content`, `keywords` 테이블) 및 저장/조회 함수 |
| `run_pipeline.py` | 위 컴포넌트를 순서대로 실행하는 수동 진입점 스크립트 |

각 컴포넌트는 독립된 책임을 가지며, 다른 컴포넌트 구현에 의존하지 않고 함수 단위로 교체·테스트 가능해야 한다.

## 데이터 흐름 & 에러 처리

1. `run_pipeline.py` 실행 → 유튜브 인기 급상승 목록 수집
2. 수집 실패 시(네트워크 오류, API 키 문제 등): 실패 사유를 출력하고 빈 목록으로 처리, 파이프라인은 중단하지 않고 요약까지 출력
3. 수집된 콘텐츠를 Claude API로 배치 처리하여 키워드 추출
4. Claude API 호출 실패 시: 해당 콘텐츠는 키워드 없이 원문만 저장, 재시도는 강제하지 않고 다음 실행에서 자연히 커버
5. 모든 저장 결과를 SQLite에 반영

## 검증 (실행 결과 요약)

매 실행 끝에 다음 형태의 요약을 콘솔에 출력한다 — 이는 개발 과정에서 "완료했다"는 주장을 실제 수치로 뒷받침하기 위한 최소 검증 장치다.

```
유튜브 수집: N건
키워드 추출: 성공 K건 / 실패 F건
```

## 테스트 방식

- 각 컴포넌트(수집기, 키워드 추출기, 저장소)는 함수 단위로 작성하여 실제 API 호출 없이 가짜 데이터로 로직 검증 가능해야 한다
- 통합 확인은 실제 스크립트를 1회 실행해 SQLite에 데이터가 쌓이는지 수동으로 확인하는 것으로 한다

## 제약 및 사전 준비 사항

- 유튜브 데이터 API 키 필요 (Google Cloud Console에서 무료 발급, 일 10,000유닛 무료 쿼터)
- Claude API 키 필요 (키워드 추출용, 사용량에 따른 소액 비용 발생)
- 실행 환경: Python, 로컬 실행(1인 사용), 스케줄링 없이 수동 실행
